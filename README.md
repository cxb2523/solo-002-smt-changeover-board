# SMT 换线计划看板

三台贴片机共线的换线排程单页工具。纯前端：原生 JS + SVG，无任何框架和 npm 依赖。

## 运行

```bash
node server.js
# 打开 http://localhost:8080
```

数据从本地 JSON 读取：

- `data/boards.json`：机台配置（槽位数、吸嘴位、已装吸嘴、贴装速度）、每块板的元件清单（位号/料号/槽位/吸嘴/贴装点数）
- `data/orders.json`：订单（产品线、板号、数量、加急标记）

样例（36 块板、36 张订单、三条产品线各 12 张单）由 `node tools/gen-data.js` 可复现生成。
样例里故意留了两处导入错误演示：`B-L2-08` 有重复位号 `R12`，料号 `P-CN2` 与 `P-IC5` 抢同一槽位 `S19`，页面顶部导入即报。

## 页面说明

- 左侧订单列表可拖动改顺序；加急订单始终先排（拖动只改变非加急单之间以及加急单之间的先后）。
- 顶部三个数随拖动即时重算：**总换线次数、最长机台时间、贴装点均衡偏差**。
- 右侧 SVG 时间轴按机台分行：蓝/紫/青块为三块产品线的板子，宽度=贴装耗时；红色段为两次贴装之间的换线，点击列出这次要拆哪些料、装哪些料、换哪些吸嘴。
- 板子元件种类超过机台槽位（需分次上料）、需要机台未装的吸嘴、吸嘴种类超过吸嘴位时，在对应订单行和时间轴板块上当场红标并写明缺什么。

## 排程取舍：优先少换线

这题的核心取舍是"换线少"与"三台机点数拉平"互相打架。本实现选 **换线优先**，
理由：换线是停线时间，一次拆/装料站约 2 分钟（`changeoverMinutes`），点数不均只影响并行节拍，
先保住总停线时间收益更大。

排序与判断规则（`app.js` 中的 `recompute` / `transition`）：

1. **加急优先**：带 `urgent` 的订单先占机台，其余按页面上的拖动顺序。
2. **逐单贪心分机**：每张订单试算分到三台机的增量换线次数，选增量最小的机台；
   增量相同（平局）时，分给当前累计贴装点数最少的机台——在不牺牲换线的前提下顺带拉平衡。
3. **同族成串**：连续两块板料号清单重叠的料站保留，只拆"上一块有、这一块没有"的料、
   装"这一块有、上一块没有"的料，贪心地让同料族的板子自然串在一台机上。

换线次数的计数口径（总换线次数 = 三台机之和）：

- 每拆下 1 种料站计 1 次，每装上新 1 种料站计 1 次；
- 元件种类数 > 机台槽位数时，超出的料需分次上料，每种超槽料额外计 2 次（拆 + 装）；
- 板子需要的某种吸嘴机台没装，每缺一种计 1 次换吸嘴；
- 需要的吸嘴种类数超过机台吸嘴位数属于硬冲突（加 50 的惩罚分，调度会尽量避开，同时红标）；
- 每台机的第一块板只算首次上料，不计换线。

机台时间 = 贴装点数 ÷ 机台速度（点/秒）+ 换线次数 × 单次换线时长。
均衡偏差 = 三台机贴装点数的 (最大 − 最小) ÷ 平均。

拖动订单顺序会改变每台机上板子的相邻关系，进而改变拆/装料集合、分机结果和三个指标，
而不是只改显示文字。
